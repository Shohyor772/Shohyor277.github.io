# Отчёт по аудиту безопасности 
---

## 1. XSS (Cross-Site Scripting)

### Описание уязвимости
XSS возникает, когда злоумышленник может внедрить вредоносный JavaScript-код в страницу, которая потом выполняется в браузере других пользователей. Например, если вывести введённые пользователем данные без экранирования.

### Исправление в коде
Во всех местах вывода данных, введённых пользователем, используется функция `htmlspecialchars()`, которая преобразует специальные символы в HTML-сущности.

**Пример исправления:**
```php
// Было (уязвимо):
echo $user['full_name'];

// Стало (безопасно):
echo htmlspecialchars($user['full_name']);

2. Information Disclosure (Утечка информации)
Описание уязвимости
При ошибках базы данных или PHP пользователь мог видеть детальные сообщения: названия таблиц, структуру запросов, пути к файлам. Это помогает злоумышленнику подготовить атаку.

Исправление в коде
В начале скриптов отключается показ ошибок, а все ошибки записываются в лог-файл на сервере.

Пример исправления:

ini_set('display_errors', 0);
ini_set('log_errors', 1);
error_reporting(E_ALL);

// При перехвате исключения показываем общее сообщение
catch (PDOException $e) {
    error_log($e->getMessage());
    die("Ошибка подключения к БД. Попробуйте позже.");
}


3. SQL Injection (SQL-инъекции)
Описание уязвимости
Если вставлять переменные напрямую в SQL-запрос, злоумышленник может изменить логику запроса и, например, получить чужие данные или удалить таблицы.

Исправление в коде
Все запросы к базе данных выполняются через подготовленные запросы (prepared statements) PDO. Данные передаются отдельно от SQL-кода.

Пример исправления:

// Было (уязвимо):
$stmt = $pdo->query("SELECT * FROM users WHERE id = " . $_GET['id']);

// Стало (безопасно):
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
$stmt->execute([$id]);

4. CSRF (Cross-Site Request Forgery)
Описание уязвимости
Злоумышленник может создать поддельную форму на своём сайте и заставить авторизованного пользователя отправить запрос на ваш сервер без его ведома.

Исправление в коде
Генерируется уникальный токен для каждой сессии, который передаётся в скрытом поле формы. При отправке сервер проверяет этот токен.

Пример исправления:

// Генерация токена
if (empty($_SESSION['csrf_token'])) {
    $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
}

// В форме:
<input type="hidden" name="csrf_token" value="<?= $_SESSION['csrf_token'] ?>">

// При обработке:
if ($_POST['csrf_token'] !== $_SESSION['csrf_token']) {
    die('Ошибка безопасности: неверный CSRF-токен.');
}

5. Include-уязвимости (Local/Remote File Inclusion)
Описание уязвимости
Если имя включаемого файла передаётся через параметр URL, злоумышленник может подставить путь к любому файлу на сервере (например, /etc/passwd) или удалённому скрипту.

Исправление в коде
Используется белый список допустимых файлов. Если запрошенный файл не в списке — доступ запрещён.

Пример исправления:

$allowed = ['index.php', 'admin.php', 'form.php'];
$page = $_GET['page'] ?? 'index.php';
if (!in_array($page, $allowed)) {
    die('Доступ запрещён');
}
include($page);

6. Upload-уязвимости (Загрузка файлов)
Описание уязвимости
Если не проверять загружаемые файлы, злоумышленник может загрузить PHP-скрипт или другой исполняемый файл и получить доступ к серверу.

Пример исправления:

$allowedTypes = ['image/jpeg', 'image/png', 'image/gif'];
$maxSize = 2 * 1024 * 1024; // 2 MB

if (!in_array($_FILES['file']['type'], $allowedTypes)) {
    die('Недопустимый тип файла');
}
if ($_FILES['file']['size'] > $maxSize) {
    die('Файл слишком большой');
}

// Переименовываем и сохраняем
$newName = bin2hex(random_bytes(16)) . '.jpg';
move_uploaded_file($_FILES['file']['tmp_name'], "uploads/$newName");
